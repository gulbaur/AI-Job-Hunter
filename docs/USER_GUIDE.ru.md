# AI Job Hunter — руководство пользователя

Подробное описание работы программы. Обзор проекта и установка — в [README](../README.md).

## Восстановление после сбоев

Блокировки теперь удерживает операционная система: оставшийся файл `.lock` сам
по себе не мешает запуску. Если программа занята ручной работой, планировщик ждёт
освобождения до часа и не расходует окно до фактического начала подготовки.
После начавшейся обработки автоматического повторного платного запуска в том же окне нет.

Закрытые вакансии архивируются отдельно. Ошибка одной карточки не останавливает
подготовку остальных независимых вакансий. Неудачная оценка или письмо сохраняются
в разделе **«Требуют внимания»**. **«Повторить подготовку»** запускает только выбранную
вакансию, использует актуальную сохранённую оценку, если она есть, и может расходовать
OpenRouter. Автоматического повтора отклонённых текстов нет. Эта кнопка не отправляет отклик.

При новом сбое планового запуска появляется локальное уведомление; одинаковая
неизменная ошибка повторно не уведомляет. Статус и журнал планировщика доступны
в приложении после открытия, даже если вкладка была закрыта во время обработки.

В настройках есть свёрнутое восстановление исключённых вакансий. Старые записи
без причины исключения автоматически не возвращаются: это могли быть ручные решения.
Новые исключения компаний отделены от ручного «Не подходит», поэтому снятие правила
снова допускает такие вакансии к отбору. Защита уже начатых и отправленных откликов сохраняется.

Ограничения страны из JobPosting сохраняются отдельно; явный запрет удалёнки или
ограничение страны имеет приоритет над общим словом Remote/Worldwide.
Прямые HH-находки веб-поиска передаются тому же браузерному читателю, если HH включён,
и учитываются в общем лимите сбора. При выключенном HH это ссылки для ручного просмотра.

Исследование компании не принимает домен по общему слову вроде Technologies или Bank.
Для неоднозначных названий можно задать известные сайты в `profile/company_domains.json`:

```json
{"Название компании": ["https://company.example"]}
```

Без достаточно надёжного источника письмо опирается на вакансию. Старые письма
и ручные правки при изменении этой проверки не перезаписываются.

## Источники, свои роли и охват

Поиск объединяет HH, публичные доски Ashby/Greenhouse/Lever и веб-находки.
Начальный список досок: Higgsfield AI, Cohere и Canonical. Это проверяемые
источники, а не утверждение, что их вакансии подходят кандидату.

- **Настройки**: все направления ищутся вместе; свои роли и исключения задаются отдельными строками.
- **Источники** в настройках: HH, сайты компаний, независимый веб-поиск OpenRouter.
- **Отчёт об источниках** внизу страницы: время проверки, карточки, лимиты и ошибки.
  Полный отчёт — `data/last_discovery.json`, история — `data/discovery_reports/`.

Сбор HH отделён от платной обработки: по умолчанию до 12 новых вакансий HH,
но до 10 оценок/писем за запуск. Денежный лимит сейчас отключён. Отобранные находки,
которые ещё не обработаны, остаются во внутренней очереди на следующие запуски;
готовые письма повторно не создаются. Старые вакансии из очереди проверяются
перед новым платным этапом. Статусы и первые даты обнаружения сохраняются.

Веб-поиск выполняется самой программой через OpenRouter Web Search (Exa), до шести запросов.
Используется существующий ключ и баланс OpenRouter, отдельного ключа Exa не нужно.
Из ответа принимаются только URL из подтверждённых поисковых цитат; модельные выдуманные URL
не считаются выдачей. Недавняя выдача кэшируется до двух часов. Python затем получает полные
описания первоисточников. Частичная или недоступная выдача явно отмечается в отчёте.

Страницы без JobPosting-разметки (astanahub, hirify, dsml.kz, сайты компаний) читает ИИ
(`page_reader.py`, с 17.11.2026): модель только классифицирует страницу (вакансия / список /
закрыта / другое) и копирует название, компанию, город и дату. Каждое поле сверяется с текстом
страницы, а описанием вакансии остаётся текст самой страницы. Из списка открываются до трёх
подходящих ссылок. Не больше 20 страниц за запуск (~$0.0002 за страницу), в общем бюджете запуска;
прочитанная страница повторно не оплачивается. Ссылки, которые программа прочитать не может
(LinkedIn, страницы без текста, сайты с HTTP 403), один раз приходят в итоговом сообщении бота.

Поисковый сниппет не считается вакансией. Поддержаны публичные API досок и
JobPosting-разметка; на странице одной вакансии сохраняется также основной
видимый текст, если разметка сокращена. Недоступные страницы, запрет robots.txt,
неподдержанная разметка и отсутствие вакансии в опубликованной доске отмечаются
отдельно. LinkedIn-ссылки сохраняются для ручного просмотра, аккаунт ботом не обходится.
Для международной удалёнки одного слова Remote недостаточно: нужна явно указанная
доступность из Казахстана/по миру; ограничения US-only и аналогичные блокируют отбор.

Внешняя английская вакансия получает английский CV и индивидуальное английское письмо; русская — русские. Общая очередь различает источник и ID. Отправщик
подключён только к HH. Для внешних площадок доступны CV, письмо и ссылка; открытие
сайта не вводит персональные данные и не отправляет заявку. После ручной отправки
её можно отметить отдельным подтверждением. Эта отметка не выдаётся за подтверждение
доставки самим сайтом.

Проверка 23.10: три доски вернули 95/114/312 опубликованных карточек, отработали
HH и шесть веб-запросов. Неоплачиваемая удалённая стажировка Platvix прошла оценку
и подготовку английского письма (около 0,0009 USD за два API-вызова). Это проверка
интеграции, а не рекомендация предпочесть неоплачиваемую работу. Повторный сбор
не создал дубликатов. Новых откликов нет. Все 120 офлайн-тестов прошли.

## Единый запуск

Откройте `run_hunter.cmd` двойным щелчком: запустится локальное приложение в браузере.
Повторный запуск открывает существующее приложение. Хостинг и новые зависимости не нужны.

- **Готовые отклики** — карточки вакансий, оценка, раскрываемые пробелы и редактируемое письмо.
  Кнопка «Сохранить изменения» записывает письмо в существующий файл черновика.
- **Найти и подготовить** — существующая цепочка поиска, оценки и писем, с общим сохранённым бюджетом.
- **Подготовить отправку** — открыть и заполнить форму HH. После проверки в окне HH
  вернитесь в приложение и введите точную фразу `ОТПРАВИТЬ ID`. Один клик отправки,
  проверка доставки и прежняя защита от повторов сохраняются. Без подтверждения
  через 10 минут форма закроется без отправки; «Отменить» закрывает её сразу.
- **Внешние сайты** — ссылка для ручной отправки, письмо и имя рекомендованного CV.
- **Настройки** — поля вакансий, исключения, лимиты, платформы, доски компаний и карьерные страницы.
- **История** — подтверждённые доставки, ручные отметки и неизвестные результаты.
- **Отчёт об источниках и журнал** — свёрнутый блок для подробной проверки.

Кнопка «Войти в HH» открывает сохранённый профиль; после ручного входа нажмите «Готово» в приложении.
Закрытие вкладки не останавливает локальную программу. Для остановки используйте «Завершить работу»
внизу страницы. Во время поиска или отправки завершение блокируется.
Интерфейс слушает только `127.0.0.1`, проверяет Host/Origin и требует случайный токен для изменений.
`.env`, CV и браузерный профиль через файловый сервер не доступны.
Открытие карточек не вызывает модель. Планировщик Windows работает отдельно от вкладки.

Консольный вариант оставлен в `run_hunter_console.cmd` для диагностики.
Следующее описание относится к нему:

Новые непросмотренные письма появляются сразу,
по одному: оценка, пробелы, CV и полный текст. Номер вакансии выбирать не нужно.
`о` открывает форму HH с отдельным подтверждением отправки или сайт компании
для ручного отклика; `р` открывает письмо в Блокноте, `и` исключает вакансию.
Enter откладывает письмо и показывает следующее, сохраняя черновик. `0` возвращает в меню.
Просмотр сохраняется при перезапуске: та же версия письма автоматически повторно
не показывается. Клавиша `п` в главном меню открывает все отложенные письма.
Изменённое письмо снова считается новым. Просмотр не помечает отклик отправленным.

В главном меню продолжение работы, отложенные письма, настройки и выход:

1. **Продолжить** (также Enter) — показать непросмотренные письма. Если их нет,
   собрать включённые источники, отсеять дубли и неподходящие вакансии, оценить
   до 10 вакансий, подготовить письма и сразу показать их. Все этапы идут
   подряд, без промежуточных вопросов. Резерв OpenRouter общий на запуск —
   по сохранённой настройке (сейчас без денежного лимита). Формы автоматически не открываются.
2. **Настройки и история** — только три пункта: «Что искать» (правила),
   «Где искать» (источники), «Общий отчёт» (история отправок и охват вместе).
   Поиск, оценка и письма выполняются через «Продолжить», без отдельных этапов меню.

Все направления ищутся вместе за один запуск: Junior/стажировки,
ML/Data Science и Applied AI/LLM/NLP/CV. Выбирать и запускать их отдельно не нужно.
В «Настройки и история → Что искать» доступны исключённые
слова, давность (1/3/7/30 дней), объём (1–10 вакансий, 1–2 страницы на группу),
фильтр стажа HH, свои роли, лимит сбора и резерв OpenRouter. Они сохраняются
в `profile/search_settings.json`. Исключения в названии действуют также на
готовые черновики. География и компании остаются в `profile/preferences.json`.
Если нужен ручной вход, введите `вход` в главном меню; программа подскажет
это при ошибке сессии. Вход и капчу проходите самостоятельно в окне браузера.

Перед отправкой выбранного отклика программа покажет реальное резюме HH и письмо
в браузере. Только точная фраза `ОТПРАВИТЬ ID` разрешает один отклик на эту вакансию.
Любой другой ответ отменяет отправку. Выбор пункта меню сам по себе её не разрешает.
После отправки выводится результат HH. Следующий отклик требует нового подтверждения.
Закрытие программы сохраняет очередь, ручные правки писем и историю в SQLite/файлах.

## По расписанию: 10:00 и 18:00 по Алматы

В планировщике Windows зарегистрирована задача **Personal AI Job Hunter** с ежедневными
триггерами 10:00 и 18:00 (фиксированное смещение Алматы +05:00).
Она запускает `.venv/Scripts/pythonw.exe -X utf8 scheduled_runner.py` без окна консоли.
Последовательность: независимый веб-поиск → HH и компании → фильтры → оценка →
исследование компании → индивидуальные письма → проверка фактов → сохранённая очередь.
Формы отклика не открываются; автоматическая отправка в расписании отсутствует.
При новых письмах появляется короткое локальное уведомление Windows.

Для работы нужны включённый компьютер, выполненный вход в Windows, интернет и действующая
сессия HH. Вкладка приложения может быть закрыта. Вход в HH и капча остаются ручными.
Пропущенные запуски Windows выполняет при доступности компьютера; повтор одного окна
блокирует `scheduled_run.py`. Отчёты: `data/windows_schedule.json`,
`data/last_scheduler_invocation.json`, `data/last_scheduled_run.json`, `data/scheduled_logs/`.

До 10 новых писем за запуск, до 20 за два плановых запуска при подходящих вакансиях.
Денежный лимит отключён (`budget_usd: null`), стоимость API учитывается в отчёте.
Изменение времени задачи: планировщик Windows; проверить/переустановить штатное расписание —
`tools/install_schedule.ps1 -Mode Status` / `-Mode Install`.


## Telegram-бот

После каждой подготовки бот присылает **одно сообщение**: сводку запуска (с расходом на ИИ) и кнопку на каждое письмо в очереди. Нажатие на вакансию превращает это же сообщение в карточку: вакансия, дата публикации, письмо и кнопки:
- «🚀 Откликнуться на HH» (только вакансии HH) — ноутбук открывает HH и заполняет форму, бот присылает скриншот формы и одноразовый 4-значный код. Отклик уходит один раз и только после кода (3 попытки, 10 минут, кнопка «Отмена»). Нужен включённый ноутбук и вход в HH в браузере программы — один раз через `hh_login.cmd`;
- изменить письмо своим текстом или «🤖 Переписать с ИИ» по вашему указанию (платно, ~$0.02–0.03, с проверкой фактов);
- отложить (письмо остаётся в списке внизу с ⏸);
- не подходит (с кнопкой «вернуть»);
- отправлено вручную — после отметки программа не отправит отклик на эту вакансию;
- файл CV (PDF, если он экспортирован рядом с docx);
- ссылка на вакансию и «⬅️ К списку писем».

После действия сообщение возвращается к списку. Бот присылает и проблемы запуска: пропущенное окно, прерванный или остановленный запуск. Отвечает бот только одному личному чату.

**Установка (один раз):**
1. В Telegram откройте @BotFather → `/newbot`, придумайте имя. Выданный токен вставьте в `.env` строкой `TELEGRAM_BOT_TOKEN=...`.
2. Привяжите свой чат: `.venv\Scripts\python.exe -X utf8 tools\telegram_setup.py` и отправьте боту показанное сообщение `/start <код>`. Программа запишет `TELEGRAM_CHAT_ID` в `.env`. Пока бот запущен, привязку не делайте: Telegram разрешает только одного читателя сообщений.
3. Запуск при входе в Windows: `powershell -File tools\install_bot_task.ps1 -Mode Install`. Проверка — `-Mode Status`.

Пока Telegram не настроен, остаются всплывающие окна Windows. Если бот не работает больше 5 минут, на сайте в боковой панели появляется «Telegram-бот не работает». Журнал — `data/telegram_logs/bot.log`: без текстов писем, CV, кодов и токена.

**Что проходит через Telegram:** тексты писем и вакансий, файл CV (только по кнопке «📎 CV»).

## Как пишутся индивидуальные письма

Режим по умолчанию — `letter_mode: personalized`. Файл `personalized.py` содержит промпты
`SYSTEM_PROMPT` (написание) и `AUDIT_PROMPT` (проверка) с общими правилами. Цель поиска, географию
и от чьего лица писать письма кандидат описывает сам в `profile/candidate.md` (образец —
`examples/profile/candidate.md`); этот текст добавляется в промпты оценки и писем. `company_research.py` ищет и читает
до двух доступных страниц компании. Сведения с чужого сайта не объявляются официальными
только потому, что там упомянута компания. Если надёжных источников нет, письмо опирается
на задачи вакансии. Источники показываются под письмом.

ИИ пишет новый связный текст, а не вставляет одинаковые CV-абзацы. Утверждения об опыте
связываются с фактами выбранного CV и `profile/confirmed_facts.json` — явными подтверждениями
пользователя. Числа, ссылки на факты, принадлежность
версии CV проверяются программой. Затем отдельная модель проверяет фактическую опору текста.
Модель проверки задаётся в `.env` строкой `OPENROUTER_AUDIT_MODEL`. Проверка не отменяет просмотр пользователем.

Кнопка «Написать индивидуально» создаёт новую версию старого шаблонного письма. Предыдущие
файлы и ручные правки не удаляются. Записи `personalized.json`, `research.json`, `selection.json`
и `package.md` сохраняют происхождение текста. Некорректный ответ не используется и не
перезапрашивается автоматически; явное создание новой версии является новым запросом.
Режим `literal` оставлен для совместимости с прежними черновиками и отдельной CLI-утилитой.

Офис подходит только в городе из `profile/preferences.json`, остальные места — только при явно указанной
удалёнке. Международная доступность всё равно требует проверки. Поиск сейчас
ограничен выбранными источниками и правилами; полный рынок не гарантируется. В HH просматриваются три
группы запросов, до двух страниц в каждой, поэтому это ограниченная выборка.
Нулевой результат не подставляет старые вакансии молча.

В HH используется **существующее резюме из аккаунта**: в живой проверке
`AI/ML Engineer`. Рекомендованный локальный DOCX отдельно показан в пакете;
он не загружается и не подменяет резюме HH. Перед отправкой проверьте содержание
резюме в аккаунте и письмо. Если в форме есть дополнительные вопросы или требуется
изменить видимость резюме, программа останавливается и ничего не выдумывает/не меняет.

Общий денежный лимит модели и писем сейчас отключён. Кэш не оплачивается
повторно; неизвестная стоимость отмечается отдельно. Ошибочные ответы не
перезапрашиваются автоматически. Рекомендация с пробелами не становится полным
соответствием; содержание и решение об отклике проверяет пользователь.

```powershell
# Предпросмотр базы: без браузера и вызовов модели.
& .\.venv\Scripts\python.exe .\hunt.py

# Полный поиск и подготовка; отправка выключена.
& .\.venv\Scripts\python.exe .\hunt.py --run

# Подготовить до 10 писем в сохранённую очередь, без открытия форм.
& .\.venv\Scripts\python.exe .\hunt.py --run --queue

# Открыть то же меню, что запускает run_hunter.cmd.
& .\.venv\Scripts\python.exe .\hunter_menu.py

# Полный сценарий с единственным разрешением одной отправки в конце.
& .\.venv\Scripts\python.exe .\hunt.py --run --send

# Продолжить последний пакет, без нового поиска и оплаты модели.
& .\.venv\Scripts\python.exe .\hunt.py --run --resume --send

# Использовать сохранённые вакансии, проверив их актуальность в HH до модели.
& .\.venv\Scripts\python.exe .\hunt.py --run --from-db
```

`--send` работает только с интерактивной консолью, требует точный ответ с ID
вакансии и не означает автоматическое согласие. Закрытый ввод и пустой ответ
не разрешают отправку. После начала отправки повтор блокируется даже при ошибке.
Капча проходится пользователем в том же окне, затем программа ещё раз проверяет
результат. Если явное подтверждение HH не распознано, состояние остаётся
`submitted_unverified` — повторять отправку нельзя до ручной проверки.

Пакет, письмо, скриншоты и отчёт каждого запуска сохраняются в `drafts/runs/`.
Указатели последнего отчёта и подготовленного пакета находятся в `data/` и
исключены из Git. Они разные: пустой поиск не теряет возможность продолжить
предыдущий пакет. Одновременные запуски блокирует `profile/hunt.lock`; после
аварии сначала проверьте, что старый процесс завершён, перед удалением этого lock.

Меню, очередь, повторное открытие базы, сохранение редакции письма и полный
цикл отправки проверяются офлайн. Браузерный тест использует локальные маршруты
вместо HH и считает отправки: пустое подтверждение — ноль, точное подтверждение —
одна, повтор — блокировка. Это не проверка всех возможных интерфейсов HH;
неизвестные вопросы, изменение условий и капча требуют участия пользователя.

Сбор до трёх вакансий через видимый браузер после ручного входа:

```powershell
& .\.venv\Scripts\python.exe .\browser_check.py

# Следующая проверка: без опыта или 1–3 года по фильтру HH.
& .\.venv\Scripts\python.exe .\browser_check.py --junior

# Повторные запуски: использовать сохранённую сессию без паузы для Enter.
& .\.venv\Scripts\python.exe .\browser_check.py --junior --reuse-session

# Расширенный поиск новых: Junior/стажировки, ML/DS, Applied AI/CV.
& .\.venv\Scripts\python.exe .\browser_check.py --junior --expanded --pages 2 --reuse-session

# Оценить только сохранённые в последнем сборе вакансии, без подстановки старых.
& .\.venv\Scripts\python.exe .\assess.py --last-collection --budget 0.02 --run
```

Поиск ограничен названиями вакансий; дополнительно отсекаются проектные/продуктовые
менеджеры, антифрод, Senior/Lead и другие явные смежные роли. Фильтр может пропускать
необычные названия, поэтому это ограниченный поиск, а не полный обзор рынка.
Обычный запуск просматривает один запрос/одну страницу. `--expanded` использует три
группы запросов, начиная с Junior/стажировок; `--pages 2` разрешает максимум две
страницы на группу. Сбор останавливается после трёх сохранённых вакансий либо по
исчерпании запросов/страниц. Если видимый счётчик показывает конец выдачи, лишняя
страница не открывается. Категория стажа `--junior` не заменяет чтение требований.

Известные ID по умолчанию пропускаются до открытия описания, повторы между
запросами не перечитываются. Для намеренного обновления известных карточек есть
`--refresh`; статусы и первые даты обнаружения сохраняются. Живой расширенный
запуск: три новые вакансии, две известные пропущены, ошибок нет.

В `data/last_browser_run.json` записываются ID только последнего сбора. Параметр
`assess.py --last-collection` оценивает именно их. Пустой список не подменяется
старыми вакансиями, при частичном сборе используются только сохранённые ID с
предупреждением. Повтор оценки использует обычный кэш. Повторный сбор заменяет
этот список, поэтому пару команд выполняйте последовательно.

Если видимый регион отсутствует, используется публичный JobPosting; если города
нет и там, он остаётся неизвестным. Сохранённый известный город не затирается пустым.
Ошибка отдельной карточки не мешает следующей. Вход, капча и ограничения доступа
останавливают сбор; `--reuse-session` их не обходит. При истёкшей сессии запустите без
этого флага и войдите вручную. Одновременный запуск одного профиля не поддерживается.

Просмотр сохранённого:

```powershell
& .\.venv\Scripts\python.exe .\main.py list --limit 20
& .\.venv\Scripts\python.exe .\main.py show <id вакансии>
```

Оценка соответствия использует две английские версии CV из `profile`:
`CV_ML_ENGINEER_EN.docx` и `CV_APPLIED_AI_EN.docx`. Исходные DOCX не меняются.
Перед отправкой удаляется начальный блок с именем и контактами; профессиональная
часть CV и текст вакансии отправляются в OpenRouter только с `--run`.

География, подтверждённая пользователем, сохранена в `profile/preferences.json`:
офис только в указанном городе; другие города и страны — только удалённо. В оценке офисные
вакансии других городов и вакансии с неизвестным удалённым форматом откладываются
до вызова модели и чтения кэша. Их пользовательские статусы не меняются. Если
удалёнка указана, отдельно напоминается о проверке доступности из Казахстана.
Сам сбор HH пока ограничен Казахстаном; этот фильтр не является поиском по миру.

```powershell
# Предпросмотр: без отправки данных и вызовов модели.
& .\.venv\Scripts\python.exe .\assess.py --limit 3

# Выполнить оценки через OpenRouter.
& .\.venv\Scripts\python.exe .\assess.py --limit 3 --budget 0.02 --run

# Оценить одну вакансию; повторный запуск использует кэш.
& .\.venv\Scripts\python.exe .\assess.py --vacancy-id <id вакансии> --run

# Подробная проверка исходных фрагментов и выводов.
& .\.venv\Scripts\python.exe .\assess.py --vacancy-id <id вакансии> --verbose
```

Ключ и модель (`OPENROUTER_MODEL`) читаются из `.env`.
Запросы ограничены ценами провайдера (`PRICE_CAP` в `assess.py`) за миллион входных/выходных
токенов. `--budget` проверяет консервативный резерв перед каждым новым запросом,
а фактическая стоимость показывается отдельно, если API её сообщает.
Ошибочные или незавершённые ответы не повторяются автоматически.
Ответы, не прошедшие проверку, учитываются отдельно в `rejected_assessments`,
вместе с сообщённой API стоимостью. Они не используются как рекомендации и
не мешают проверить остальные вакансии. Повтор такого же отклонённого ответа
требует явного `--retry-rejected --run`; по умолчанию нового платного запроса нет.

Рекомендация — «рассмотреть», «с заметными пробелами» или «низкий приоритет».
Это оценка соответствия, а не вероятность найма. Модель выбирает ID готовых
фрагментов, а программа подставляет исходные цитаты и проверяет принадлежность
выбранному CV. Неизвестные ID и ссылки на другую версию CV отклоняются. Это
устраняет перефразирование цитат, но смысловые выводы по-прежнему требуют просмотра.
Частичное совпадение помечается отдельно. Только частичные совпадения, явное
требование стажа от 2 лет или офис в Астане не дают автоматической рекомендации
«рассмотреть» без оговорок для поиска уровня Junior. Это консервативная
эвристика, а не доказательство невозможности найма.
Смежные роли из старой базы не отправляются модели; для отдельной проверки можно
явно задать `--include-other-roles`. Их пользовательские статусы не меняются.
Результаты сохраняются в таблице `assessments` существующей базы. Неизменённые
CV и вакансии оцениваются повторно из кэша, без нового вызова. Изменение CV,
вакансии, модели, промпта или месяца оценки создаёт новую оценку. Пользовательский
статус вакансии и дата её первого обнаружения сохраняются.

Настройки, CV, браузерная сессия и базы остаются локальными и указаны в `.gitignore`.
Сам браузер и модуль оценки не отправляют отклики. Доступ к HH API остаётся
необязательным. Перед передачей данных площадок внешним сервисам учитывайте
применимые условия источника; браузерный доступ сам по себе не отменяет их.

Подготовить CV и письмо по сохранённой, уже оценённой вакансии:

```powershell
# Предпросмотр без отправки данных и расходов.
& .\.venv\Scripts\python.exe .\prepare.py --vacancy-id <id вакансии>

# Выбрать факты через OpenRouter и собрать пакет для просмотра.
& .\.venv\Scripts\python.exe .\prepare.py --vacancy-id <id вакансии> --run

# При необходимости явно выбрать другую версию CV.
& .\.venv\Scripts\python.exe .\prepare.py --vacancy-id <id вакансии> --cv applied_ai --run
```

`prepare.py` использует только актуальную сохранённую оценку. Для Data Scientist,
ML и Computer Vision по умолчанию выбирается ML CV; для LLM/RAG — Applied AI.
`--cv ml_engineer` и `--cv applied_ai` задают выбор явно, `--cv auto` оставляет его
модели. Выбор пользователя имеет приоритет. Это правила представления опыта,
а не гарантия соответствия вакансии.

Модель выбирает 2–3 ID фактов из русского CV; программа проверяет их принадлежность
одной версии и собирает письмо шаблоном с дословными исходными формулировками. Это прежний режим `literal`; приложение по умолчанию использует `personalized.py`.
Новые утверждения об опыте, придуманные метрики, даты и стаж модель не пишет.
Для обычного Data Scientist отбираются прежде всего факты оценки, обучения и
инференса моделей, а не общие RAG/API-абзацы. Это всё ещё требует смысловой проверки:
оценка речи не подтверждает опыт табличных бустингов.

В `drafts/hh-ID/auto-HASH/` создаются `letter.txt`, `package.md` с CV и пробелами,
а также кэш выбора фактов. Перед запуском проверяется география. Бюджет по умолчанию
0,01 USD, меняется через `--budget`; повтор использует кэш. Отклонённые ответы не
оплачиваются повторно без `--retry-rejected --run`. Сообщённая API стоимость хранится
и для отклонений. Редактированные письма и пакеты не перезаписываются. Изменение
входных фактов/вакансии/оценки/настроек выбора создаёт другой каталог. Пустой или
неподходящий набор фактов требует ручного просмотра. Резюме в аккаунте HH, поля
формы и актуальность вакансии нужно проверить отдельно; форм и отправки в модуле нет.

Если добавить исключения в `profile/preferences.json: excluded_companies`,
оценка и подготовка проверят их до чтения кэша и вызова модели.
